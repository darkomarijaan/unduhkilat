# Purwarupa: rantai jump SSH dengan `russh`

Tanggal: 2026-11-07. Kode purwarupa sudah dibuang (hidup sebentar di `spikes/ssh-jump/`, riwayat git menyimpannya).

## Keputusan

**Pakai `russh` 0.65.1.** Semua skenario yang diminta Task 1 terbukti dengan server dan klien `russh` di loopback, di Windows, build release.

| Skenario | Hasil |
|---|---|
| Login password langsung; password salah | Berhasil / ditolak (`AuthResult::success()` false) |
| Login kunci ed25519 berfrasa sandi lewat satu lompatan (klien → B → A) | Berhasil; frasa sandi salah gagal saat `decode_secret_key` (sebelum menyentuh jaringan) |
| Rantai tiga lompatan (klien → C → B → A) | Berhasil |
| Handler `check_server_key` menerima sidik jari dan bisa menolak | Sidik jari yang dilihat klien sama persis dengan milik server (`SHA256:…`); menolak memberi galat `Unknown server key` |
| Lompatan yang menerima TCP tetapi tidak pernah membalas | Batas waktu 1 s terpicu tepat 1,00 s |
| Pembatalan oleh pengguna | `tokio::select!` menghentikan sambungan dalam 204 ms |
| Menutup satu lompatan dari tugas lain | `Handle::disconnect` menutup lompatan itu **dan** lompatan di dalamnya (`is_closed()` true untuk keduanya) |

## Resep (yang perlu Task 9 dan 10)

Versi dan dependensi:
- `russh = "0.65"` (fitur bawaan sudah cukup). `ssh-key` tidak perlu menjadi dependensi langsung: `russh::keys::{PrivateKey, PublicKey, Algorithm, HashAlg, decode_secret_key, PrivateKeyWithHashAlg, PublicKeyOrCertificate}` dan `russh::keys::ssh_key::LineEnding` sudah diekspor ulang (`ssh-key` 0.7.0-rc.11, rilis kandidat).
- `rand = "0.10"` hanya untuk membuat kunci di uji (`PrivateKey::random(&mut rand::rng(), Algorithm::Ed25519)`, `key.encrypt(&mut rand::rng(), "frasa")`, `enc.to_openssh(LineEnding::LF)`). Jadikan `dev-dependency`.
- **Penting untuk Windows:** `russh` membawa `aws-lc-rs`, yang di Windows butuh NASM kecuali fitur `prebuilt-nasm` aktif. Di workspace UnduhKilat fitur itu **sudah aktif** (lewat rustls dari `librqbit`/`reqwest`), jadi `russh` langsung terbangun. Proyek terpisah di luar workspace gagal dengan "NASM command not found"; purwarupa ini perlu `aws-lc-rs = { version = "1", features = ["prebuilt-nasm"] }`. Jangan menghapus rustls dari workspace tanpa memeriksa ini.

Klien:
- `client::Handler` memakai `async fn` biasa (tanpa `async_trait`). `check_server_key(&mut self, k: &PublicKeyOrCertificate) -> Result<bool, Error>`; untuk `PublicKeyOrCertificate::PublicKey { key, .. }` sidik jari SHA256 = `key.fingerprint(HashAlg::Sha256).to_string()`, berformat `SHA256:<base64 tanpa padding>` (sama dengan `ssh-keygen -lf`). Jenis kunci untuk `host_keys.key_type`: `key.algorithm().to_string()`.
- Tiap lompatan: `client::connect_stream(Arc<client::Config>, stream, handler) -> Handle<H>`. `stream` apa pun yang `AsyncRead + AsyncWrite + Unpin + Send + 'static`. Lompatan pertama memakai `TcpStream` (atau aliran dari `ftp::connect_tcp`); lompatan berikutnya memakai `prev.channel_open_direct_tcpip(host, port as u32, "127.0.0.1", 0).await?.into_stream()`.
- `handle.authenticate_password(user, pw)` dan `handle.authenticate_publickey(user, PrivateKeyWithHashAlg::new(Arc::new(key), None))` (untuk RSA, hash dari `handle.best_supported_rsa_hash().await?.flatten()`). Hasil `AuthResult::success()`.
- Pembatalan: bungkus seluruh tahap dengan `tokio::select!` dan `CancellationToken`; batas waktu per tahap dengan `tokio::time::timeout` (soket tidak punya batas waktu sendiri untuk jabat tangan).
- Menutup: `handle.disconnect(russh::Disconnect::ByApplication, "bye", "en").await`.
- Pesan galat sambungan jabat tangan pada penolakan kunci host berupa string `"Unknown server key"`; galat ini harus dipetakan oleh `ssh.rs` ke `ErrHostKeyUnknown` (bukan ditampilkan mentah), karena penolakan terjadi di dalam handler.

Server (untuk harness Task 9):
- `server::Server::new_client(&mut self, Option<SocketAddr>) -> Handler`; `server::Handler` memakai `async fn`: `auth_password`, `auth_publickey(user, VerifiedPublicKey<'_>)` (bandingkan `public_key.key_data()`), `channel_open_direct_tcpip(channel, host, port, orig_addr, orig_port, reply: ChannelOpenHandle, session)` (panggil `reply.accept().await`, lalu salin dua arah antara `TcpStream::connect(host:port)` dan `channel.into_stream()` dengan `tokio::io::copy_bidirectional`; tidak memanggil `accept` = ditolak), `channel_open_session`.
- Konfigurasi: `server::Config { keys: vec![PrivateKey], auth_rejection_time: 5 ms, auth_rejection_time_initial: Some(ZERO), ..Default::default() }` agar uji penolakan cepat. Jalankan dengan `tokio::spawn(async move { server.run_on_socket(cfg, &listener).await })` (soket harus tetap hidup selama server).
- Mengganti kunci host untuk uji "kunci berubah": server baru dengan `Config.keys` lain pada alamat yang sama (tidak ada API untuk mengganti kunci server yang berjalan); harness Task 9 mengimplementasikan `rotate_host_key` dengan menghentikan dan menjalankan ulang server pada port yang sama.

## Yang mengejutkan

- Dependensi `ssh-key` adalah rilis kandidat (`0.7.0-rc.11`) yang ikut `russh`; versi tidak perlu dipin tetapi pembaruan `russh` bisa membawa perubahan API.
- `aws-lc-rs` + NASM (lihat di atas).
- `async_trait` tidak dipakai: trait `Handler` memakai `impl Future` langsung.
